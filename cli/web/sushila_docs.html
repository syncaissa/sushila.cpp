Sushila documentation

Sushila runs AI models on your own computer: chat, code, images, music and video. One program, sushila (sushila.exe on Windows), does everything; the web page it serves is the user interface. The commands are the same on Windows, macOS and Linux.

Getting started

  1. Download sushila.exe (Windows) or sushila (macOS, Linux) for your system.
  2. Run it: double-click it, or in a terminal type sushila serve. The first time it installs the engine for your GPU (NVIDIA: CUDA; AMD and Intel: Vulkan; Apple: Metal; otherwise the CPU) and a first model. The first model depends on the computer: Qwen3 4B (about 2.5 GB) with a GPU of 8 GB or more, a Mac with Apple silicon and 16 GB or more, or 16 GB of memory without a GPU (if the disk has room); otherwise Qwen2.5 0.5B (about 535 MB). The log says which one and why.
  3. Open http://localhost:7874/ in a browser (double-clicking opens it for you).

To check that everything works: sushila selftest. It installs what is needed, asks the small model (or the 4B model, if installed) one question and ends with PASS (exit code 0) or says what failed.

All commands

Type them in a terminal. Every command accepts --json (machine-readable output), --quiet and --data-dir <folder>. sushila --help and sushila <command> --help show the details.

CommandWhat it does
sushila (no command, or double-click)Starts the server and opens the web page in the browser.
sushila selftestEnd-to-end check: engine, the small default model (or the 4B one if installed; --pack picks another), one answer. Exit code 0 = everything works.
sushila doctorChecks this computer: GPU, driver, engine build, free disk, the port, the home folder, every pack file's SHA-256. Each line says OK, WARN or FAIL, with the command that fixes it.
sushila assistant ["<question>"]Ask Sushila how Sushila works: answers from this documentation and live facts about this computer, by the largest installed text model (no question: keeps asking; /exit ends). Also on the page (Help → Ask Sushila) and in the server window. With a model under 3B parameters it quotes the matching sections and their commands instead of writing an answer (small models invent steps); install a 3B+ chat model, e.g. sushila install qwen3-4b-instruct-2507, for answers in its own words.

Serving
sushila serve [<pack>...]Starts the server: web page, API and queue, and the named packs (default: the first installed one).
sushila serve --port 8844Another port (default 7874).
sushila serve --publicReachable from other machines (listens on all addresses); they need an access key.
sushila serve --public --openNo key needed for chat and generation (trusted networks only).
sushila serve --standardPlain models instead of Accelerated (Sushila's precomputed files off).
sushila start <pack> [--standard]Starts a model in the running server.
sushila stop <pack>Stops a model.
sushila stopStops the whole server.
sushila statusWhat is installed, whether the server runs, which models run (Accelerated or Standard).
sushila psRunning models: mode, port, parallel slots, uptime, memory and GPU memory.
sushila top [--interval 2]The same, refreshed every 2 s, with GPU use and the last tokens/s (Ctrl+C ends).
sushila mode <pack> standard|acceleratedSwitches a running model at once; otherwise remembered for its next start.
sushila idle <minutes>|offUnloads models nobody used for that long; the next request loads them again (it waits while the model loads).
sushila limit [--threads N] [--parallel N] [--context N] [--gpu-layers N]Engine limits used when a model starts next (no flags: shows them).
sushila config list | get <key> | set <key> <value>The settings (port, enginePort, threads, contextSize, gpuLayers, parallel, idleMinutes, keepCopy, catalogUrl, ticker), checked before they are saved.
sushila queue [list] | pause [<id>] | resume [<id>] | cancel <id>The running server's background queue (without an id: the whole queue).
sushila history [show <id>]Past queue jobs with prompt, settings, seed, times and the output file.
sushila open [admin|docs|assistant]Opens the page in the browser.
sushila example <pack> [curl|python|js]A working API request for this computer (with its local token) and for other machines (with an access key).
sushila share on [--open] | off | qrOther machines: on makes the next sushila serve listen on the network (keys needed unless --open), off stops sharing at once, qr prints a QR code of the network address for a phone.
sushila https <domain>HTTPS for a domain: writes a Caddyfile (Caddy forwards to this server), allows that host name, prints the steps; offers to start Caddy if it is installed. Installs nothing itself.
sushila homeSushila's home folder: where model-packs, settings, logs and the engine live. Sushila remembers it in one small text file in your own settings folder, which every user can write without admin rights: Windows %APPDATA%\sushila\home (C:\Users\<you>\AppData\Roaming\sushila\home), macOS ~/Library/Application Support/sushila/home, Linux ~/.config/sushila/home. It holds one line, the folder's path, which you can also edit by hand; sushila home prints where it is. Sushila reads it at every start and goes straight there. It is the only file Sushila keeps outside its home folder. If it is deleted, Sushila searches again (and writes it again); if it finds no home, it asks for the folder of your existing home, or starts a new one when you press Enter. The first time, it searches the usual places (the system's app-data folder, next to the program, the current folder, ~/sushila, Documents, Downloads); if it finds several homes it asks which one to use. sushila home <folder> makes another folder the home (replacing the remembered one); sushila home --reset forgets it so the next start searches again; --data-dir <folder> uses a folder for one command only. The home is also printed every time the server starts. (sushila location is the same command.)
sushila urlThe addresses: Sushila page (e.g. http://localhost:7874/), Engine page (http://localhost:7874/admin, this computer only), the OpenAI-compatible API, and the address for other machines when serving on the network. The same block is printed every time the server starts, in the terminal or in the window that opens when you double-click sushila.

sushila bench <pack> [--prompt ..] [--runs 3]Speed on this computer in Standard and Accelerated (tokens/s for text, seconds for images, music and video), the speedup, saved in bench/ in the home folder.
sushila eval <pack> [--n 20]Accuracy on 20 built-in grade-school math questions, in Standard and Accelerated.

While a server runs, install, remove, engine install, start and stop are sent to it and you see its progress: the server is the one place that changes anything, so the web page and the commands always agree.

Windows, macOS, Linux

The commands are identical. What differs is how you open a terminal, how you call the program, and a first-run security prompt.

Windows

Terminal: PowerShell, Command Prompt or Git Bash.
In the folder of the file: .\sushila.exe serve
Anywhere: put sushila.exe in a folder on your PATH, then sushila serve.
First run: SmartScreen may say "unknown publisher": More info → Run anyway.

macOS

Terminal: Terminal or iTerm.
chmod +x sushila once, then ./sushila serve
Anywhere: sudo mv sushila /usr/local/bin/, then sushila serve.
First run: if macOS blocks it, System Settings → Privacy & Security → Open Anyway (or xattr -d com.apple.quarantine sushila).

Linux

Terminal: any shell.
chmod +x sushila once, then ./sushila serve
Anywhere: sudo mv sushila /usr/local/bin/, then sushila serve.
NVIDIA: a recent driver is enough (the CUDA runtime comes with the engine).

Serving and the web page

sushila serve runs one web server on one port (default 7874). The page at http://localhost:7874/ and the Sushila Station desktop app show the same screens (also through your internet link, for you as its owner). A sidebar on the left has:

  • Generate: Generate Images, Generate Music and Songs, Generate Video, Generate Code, Chat. Each Generate page has a model picker at the top (the installed packs of that kind, in each mode) with Start and Stop.
  • Your work: myContent, Queue.
  • This computer: Model packs, Engine, Internet link, Logs, Settings.
  • Help: Ask Sushila.

Pictures, songs and videos always go to the Queue: they are made in the background, so the page or the app can be closed. A notice says when one is ready; it is then in myContent with all its prompt details. Chat and Code answer live; Run in background sends a long answer to the Queue.

The green Sushila Engine button at the top left shows whether the engine runs. Clicking it opens the engine panel (Start, Stop, Download or Upgrade the engine) and the list of model packs, with tabs by kind (Chat, Code, Pictures, Music, Video, with counts), search, and order (installed first, date installed, running first, name, size). Accelerated and Standard are separate lines.

  • Engine: a health line (All good; Working, with notes; Needs attention), GPU, memory, disk, processor, server uptime, crashes, engine build and home folder, and 🧹 Make space.
  • Logs: the full log with a filter, and Crashes below it.
  • Settings: limits, where files go, keep popular packs ready, and more.
  • Internet link: see Temporary internet URL.

At the top right, Sign in (your sushila.ai e-mail and a one-time code: "Sign in to create links to your creations and share"). When signed in, your e-mail opens the account window with your shared links (views, Copy link, Open, Delete link) and Sign out. The Station app also has Open in browser.

Visitors from other machines (sharing on, access key) and anyone without this computer's token see only the Generate pages, their own Queue and Ask Sushila. Model packs, Engine, Internet link, Logs, Settings, myContent and Sign in stay on this computer (and for the link's owner).

Pages have their own addresses: /#pictures, /#music, /#video, /#code, /#chat, /#mycontent, /#queue, /#packs, /#engine, /#link, /#logs, /#settings, /#help. Old addresses still work and land on the new pages: /admin and /#admin → Engine; #admin/packs → Model packs; #admin/logs → Logs; #admin/settings → Settings; #library → myContent; #assistant → Ask Sushila; /install/<pack> → Model packs, asking to install that pack.

Each running model's engine listens on an internal port (7875, 7876, …) on 127.0.0.1 only; the server forwards to it, so only the one port is ever exposed.

Accelerated or Standard: Accelerated uses Sushila's precomputed files for the model (faster); Standard is the plain model, as Ollama or stock llama.cpp would run it. Choose the mode in the model picker of a Generate page (each pack is listed in both modes), or start with --standard.

One model pack at a time: starting a pack (a Generate page, Model packs or sushila start) stops the others after asking. The terminal and Ask Sushila need no model: the Sushila helper answers from the live state (installed and running packs, where pictures are saved, which packs fit, the GPU), maps "how do I make a picture / song / video" to the steps with the packs installed here, and quotes this documentation; a chat model, when one runs, answers free-form questions, and when none runs the helper says how to start one and what that stops. Pictures are saved in outputs/images/<date>/ in the home folder (Show in folder, Copy path under each one).

The server window

The window where sushila serve runs (it opens when you double-click sushila) takes typed lines:

  • A command, with or without the word sushila (ps, status, install qwen3-4b-instruct-2507), runs right there. Commands that delete or change things (remove, uninstall, clean, update, restore, import, share on, keys remove, home <folder>) ask Run this? [y/N] first. Commands that run until Ctrl+C (top, logs -f, watch) belong in another terminal: Ctrl+C here stops the server.
  • A question (how do I add a coding model?) is answered by the Sushila assistant, with the sections it used.
  • A mistyped command (instal qwen) gets a suggestion (with a small model, found by spelling and by matching words to commands and pack ids) (Did you mean `sushila install qwen`? Run it? [y/N]); nothing runs without a yes.
  • ? lists the important commands, urls the addresses, stop stops the server.

The screen. The window is your normal terminal (Windows Terminal or the Windows console, macOS Terminal, any Linux terminal): the output of the server and of your commands is printed as ordinary lines, so the terminal's scroll bar, mouse wheel, selection and copy work as always, and only the last rows are kept live: one progress bar per download job (the whole job's percentage, then the current file's), the sushila> input line and the ticker. Commands typed here run in the background, so questions are answered while something installs; !<command> runs a command of the system shell. Keys are read one at a time, so your typing is never mixed with output, a resize redraws everything, and blank lines are left out. Up/Down bring back earlier lines, Esc clears the line, clear empties the window; Ctrl+C stops the server (twice: at once). The server runs under the screen as a child process; if it crashes it is restarted and the screen stays. Without a terminal (a service, output to a file, SUSHILA_TUI=0) the plain window is used.

Typing, copy and paste. A blinking block cursor shows where your typing goes. copy puts the last answer of the assistant on the clipboard; copy urls the addresses. Any text can be selected with the mouse and copied with a right-click (or Enter), and pasted with a right-click or Ctrl+V; in the Windows console the window menu (click the icon at the top left) also has Edit, Copy and Paste. A terminal window cannot hold buttons; the web page has them.

Processing. After Enter the input line shows a moving "processing request... N s" message in yellow until the line is done; typing waits until then (a question from the command, such as [y/N], can be answered). Ctrl+C cancels a running command.

The ticker (optional, off unless sushila config set ticker on). The bottom line of the window scrolls, like an LED message board, one short sentence for every command ("To add a new model pack: sushila install <pack> …", with this server's real addresses), with live news in between (models running and their mode, the queue's job and progress, GPU memory, requests served). Everything else scrolls above it; download progress is kept to one row, with a bar that fills as the download goes, so it never runs into it. It has no keys of its own (every typed line is a command or a question); type ? for the important commands. ticker off / ticker on hide or show it; sushila config set ticker off keeps it off. It is off by itself when the output is not a terminal, with --json or --quiet, with TERM=dumb or SUSHILA_TICKER=0, and in windows narrower than 40 columns. Windows: escape sequences and UTF-8 are turned on for the console at start (Windows Terminal and the classic console); where symbols cannot be shown it uses ASCII. On exit (stop, Ctrl+C, a crash) the window is left as it was.

myContent, AI labels and sharing

Everything Sushila makes is saved in your files folder (Documents/Sushila: Images, Music, Videos; see Files and folders) and listed on the myContent page: search, sort, Where are my files, delete to the trash, restore or delete for good. Every file carries a machine-readable AI-generated label in its metadata (PNG: XMP and text fields; MP3: ID3 tags; WebM: Matroska tags) with the model, the prompt and the notice “Generated by a user with sushila.cpp on their local machine. To report abuse: https://sushila.ai/reportabuse. You too can create unlimited free pictures, music and videos on your PC or laptop with sushila.cpp, downloadable at https://sushila.ai/install”. The picture or sound itself is not changed.

Upload and get link (myContent and the Generate pages) uploads one file to sushila.ai and copies its link (sushila.ai/c/sushila.ai/s/<account>/<id>lt;12 characterssushila.ai/s/<account>/<id>gt;, unique for each file). It needs a sushila.ai account: your e-mail and a code sent to it each time you sign in, no password. The link page shows the AI-generated label, the notice, a Report abuse link and its number of views. All uploaded files are visible to everyone who has the link; you may delete them at any time at sushila.ai/mycontent. Uploads for free accounts may be deleted at any time. Inappropriate uploads will be deleted and reported. Manage your uploads at sushila.ai/mycontent (or your shared links in the account window: click your e-mail at the top right).

Server status, popular packs, making space

The green Sushila Engine button at the top left always shows whether Sushila Engine runs, and the Engine page has the health line; when it does not run, the page says how to start it (Start Sushila, double-click sushila.exe, or sushila serve) or to install it from sushila.ai/install. Keep popular model packs ready (a switch in Settings, or sushila config keepPopular true) downloads the popular packs that fit this computer (chat, code, pictures, songs, video) one at a time in the background, keeps 10 GB free on the disk, and keeps them installed. 🧹 Make space (on the Engine page and on myContent) lists every model pack with Remove, every picture, song and video (largest first, with where it is) with Delete permanently, and the trash with Empty trash; Upload and get link first is recommended, so a copy stays on sushila.ai. Every file Sushila makes records where it was made: on the user's own computer, or on a remote Sushila Engine for someone on another device.

Temporary internet URL

The Internet link page (only on this computer) creates and stops a link like https://sushila.ai/localhost/<20 hex characters>/ that reaches this Sushila Engine from anywhere, through a Cloudflare quick tunnel (cloudflared, fetched once from files.sushila.ai and checked by its SHA-256). It needs your sushila.ai sign-in (e-mail and a one-time code). At the first start Sushila asks whether to create a link to your app (then your e-mail and a one-time code). The link and its access key stay the same from start to start and are printed in its window; an old link you did not delete leads to the newest one. The Internet link page can make a new key and turn opening the link at start on or off. When the computer is off, the link explains how to restart Sushila there. Visitors need the access key and see only the Generate pages, their own Queue and Ask Sushila; Model packs, Engine, Internet link, Logs, Settings, myContent and your files need this computer's own token, which only pages opened on this computer get. Stop (Internet link page) or Delete at sushila.ai/mycontent → Internet links ends a link at once; that page also explains how it is kept secure.

Other machines and the internet

sushila serve --public --port 8844      # listens on all addresses
sushila keys add alice                  # prints a key once, e.g. sk-sushila-…
  • Browser: http://<server address>:8844/; the page asks for the key once and the browser remembers it.
  • From the internet: open the port in the firewall (and the router), then http://<public IP>:8844/.
  • Model packs, Engine, Internet link, Logs, Settings and myContent are never available from other machines, with or without a key.
  • --open: no key needed for chat and generation; anyone who can reach the port can use your GPU.
Plain http:// sends keys unencrypted. For use over the internet, put HTTPS in front: Cloudflare Tunnel, Caddy or nginx (any reverse proxy that forwards to the port works).

Managing Sushila: no password

  • Model packs, Engine, Internet link, Logs, Settings and myContent have no password. They open only on this computer (http://localhost:7874, checked against the real connection) and for you through your internet link (signed in to sushila.ai as the account that made the link).
  • Other machines (sharing on the network, access keys) get the Generate pages, their own Queue, Ask Sushila and the API only.
  • The commands run as you, on this computer, and need nothing more.

API (OpenAI-compatible)

curl http://localhost:7874/v1/chat/completions \
  -H "Authorization: Bearer <key>" -H "content-type: application/json" \
  -d '{"model":"qwen3-4b-instruct-2507","messages":[{"role":"user","content":"Hello"}]}'
PathWhat
/v1/chat/completions, /v1/completionsText (streaming supported); "model" names a running pack.
/v1/modelsThe running models.
/v1/images/generationsImages.
/v1/video/…, /v1/music/…Video and music jobs (used by the page).
/api/stateInstalled packs, running models, actions in progress.
/api/queueThe background queue.
/healthThe server is alive (200). For process monitors.
/ready200 when at least one model is loaded and answering, else 503. For load balancers.
/metricsPrometheus counters: requests by model and status, requests in flight, 429 refusals, time per request, slots, queue (this computer or a key).

Many users

  • Parallel slots: each text model serves several requests at once (continuous batching). Sushila chooses the number from the GPU memory left after the model (1-16; Settings → "Parallel requests per model", 0 = automatic).
  • When busy: up to 4 × slots requests per model are accepted (the rest of the slots' work waits inside the engine); beyond that the answer is 429 with Retry-After: 2, which OpenAI clients and proxies retry by themselves.
  • Request ids: every answer carries x-request-id (yours, if a proxy sends one); each request is one line in the log (api <id> <caller> <model> <path> -> <status> in <ms>).
  • More machines: run sushila serve --public on each and put a load balancer in front (it can use /ready); the API keeps no per-user state, so any machine can answer any request.

Any OpenAI client works: base URL http://<server>:<port>/v1 and the access key as the API key.

The model-packs folder

Every model pack is one folder inside model-packs: the model files plus sushila-pack.json (its name, how to run it, every file's SHA-256 and Sushila's signature). Adding a model is just adding a folder:

  1. Download the pack's file (one .zip or .sushilapack per pack).
  2. Unzip it into model-packs, so you get model-packs/<pack>/.
  3. Within a few seconds the running server finds it, checks the signature and every file, and the model is available on the Generate pages and Model packs. No restart. The log says new pack in …: <pack> verified and available.

Removing a folder removes the model (it is stopped first if it runs). A folder that fails the checks is listed on Model packs with the reason and is never run. sushila install <pack>, sushila install <file>.zip and the Model packs page create exactly the same folders. Big packs are checked once: a file is read again only if its size or date changes.

WhereWhich folder
Defaultmodel-packs in the data folder (below)
Everything in one place (e.g. a USB drive)a model-packs folder next to sushila / sushila.exe: used when it exists
Anywhere else--packs-dir <folder> or the environment variable SUSHILA_PACKS

sushila engine info shows which folder is used.

Your own model (GGUF)

Any text model in GGUF format (the files Ollama, LM Studio and llama.cpp use, e.g. from Hugging Face) can be added:

sushila install hf:Qwen/Qwen2.5-7B-Instruct-GGUF/qwen2.5-7b-instruct-q4_k_m.gguf     # from Hugging Face (@revision optional)
sushila install C:\Users\me\Downloads\my-model.gguf                                # a file you have

or drop the .gguf file (or a folder holding it) into model-packs, or use Model packs → "Add from Hugging Face".

  • If we precomputed it (the file is byte for byte one of our packs' models, compared by SHA-256), it becomes that signed pack: only the precomputed files are downloaded, and Accelerated is available.
  • Otherwise it is listed as your own model, not verified by Sushila, and runs in Standard mode (no precomputed files). A Hugging Face download is checked against the SHA-256 Hugging Face lists for it, and its repository and revision are recorded.
  • Split files (-00001-of-0000N) load from the first part; a vision projector (a file named *mmproj*) is used with it.
  • Hugging Face's original format (safetensors with config.json) is not run directly: use its GGUF version, or convert it with llama.cpp's convert_hf_to_gguf.py.

Files and folders

Created the first time; no administrator rights are needed. The program itself can live anywhere. Two places: your files (pictures, songs, videos) in your Documents folder, where you look for them and your backup (OneDrive, iCloud, Time Machine) already copies them, and Sushila's own folder (model packs, the engine, settings, logs), which is large and belongs to this computer, so it is never synced or roamed.

Your files: Images/, Music/ and Videos/, one folder per day. Choose another folder in Settings → Where my files go (with or without moving what is there). If Windows' Controlled folder access (ransomware protection) blocks Sushila from Documents, the page says so and how to allow it; until then the files go to outputs/ in Sushila's own folder.

Before build 27 everything was in %APPDATA%\ai.sushila.hoststation (macOS ~/Library/Application Support/ai.sushila.hoststation, Linux ~/.local/share/ai.sushila.hoststation). The first server start of a newer build moves that folder to the new place, and the page asks once whether to move your pictures, songs and videos to Documents or keep them where they are.

Troubleshooting

  • First step, always: sushila selftest, then sushila logs -n 60.
  • "port is busy": another server already runs (sushila status), or use --port.
  • A model does not start: its engine output is in logs/<pack>.log. If the GPU engine cannot load a model (e.g. an old driver), Sushila switches to the next engine (CUDA → Vulkan → CPU) by itself and says so in the log; sushila engine install tries the GPU again after a driver update.
  • Slow: sushila engine info shows whether the GPU is used; the model's log shows how many layers are on the GPU.
  • A download stopped: run the same command again; it resumes.
  • A pack seems damaged: sushila verify <pack>; reinstall it if a file is listed.
  • It crashed: Sushila restarts itself; Logs → Crashes shows why (exit code or signal, the error, the last log lines).
