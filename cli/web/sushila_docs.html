Sushila documentation

Sushila runs AI models on your own computer: chat, code, images, music and video. One program, sushila (sushila.exe on Windows), does everything; the web page it serves is the user interface. The commands are the same on Windows, macOS and Linux.

Getting started

  1. Download sushila.exe (Windows) or sushila (macOS, Linux) for your system.
  2. Run it: double-click it, or in a terminal type sushila serve. The first time it installs the engine for your GPU (NVIDIA: CUDA; AMD and Intel: Vulkan; Apple: Metal; otherwise the CPU) and a small model, and asks you to choose an admin password.
  3. Open http://localhost:8765/ in a browser (double-clicking opens it for you).

To check that everything works: sushila selftest. It installs what is needed, asks the smallest model one question and ends with PASS (exit code 0) or says what failed.

All commands

Type them in a terminal. Every command accepts --json (machine-readable output), --quiet and --data-dir <folder>. sushila --help and sushila <command> --help show the details.

CommandWhat it does
sushila (no command, or double-click)Starts the server and opens the web page in the browser.
sushila selftestEnd-to-end check: engine, the smallest model, one answer. Exit code 0 = everything works.
Engine and model packs
sushila engine installInstalls Sushila.cpp for this computer's GPU (CPU only when there is no usable GPU).
sushila engine install --build cpuForces a build: cpu, vulkan or cuda.
sushila engine infoEngine version, GPU, data folder.
sushila packsThe model packs you can install (--all also lists packs for other hardware).
sushila install <pack>Downloads a pack and checks the Sushila signature and every file's SHA-256. Several packs at once are fine.
sushila install <file>.sushilapackInstalls a pack file (from a USB drive or another computer), with the same checks.
sushila listInstalled packs.
sushila verify [<pack>]Checks every file of installed packs against its SHA-256.
sushila remove <pack>Removes a pack and its files.
Serving
sushila serve [<pack>...]Starts the server: web page, API and queue, and the named packs (default: the first installed one).
sushila serve --port 8844Another port (default 8765).
sushila serve --publicReachable from other machines (listens on all addresses); they need an access key.
sushila serve --public --openNo key needed for chat and generation (trusted networks only).
sushila serve --standardPlain models instead of Accelerated (Sushila's precomputed files off).
sushila start <pack> [--standard]Starts a model in the running server.
sushila stop <pack>Stops a model.
sushila stopStops the whole server.
sushila statusWhat is installed, whether the server runs, which models run (Accelerated or Standard).
sushila urlThe address of the web page.
Generating from the terminal
sushila run <pack> "<prompt>"One answer (printed), or one picture, video or song (saved). Uses the running model if there is one.
... --out file.pngWhere to save; images also take --size 1024x1024 --seed 42, video --size 1280x704 --frames 121, music --lyrics "..." --duration 60 (the prompt is the style).
Security and logs
sushila passwordSets the admin password, or changes it (asks the current one first).
sushila password --resetLost the password: sets a new one without the old one. Only on this computer.
sushila keys add <name>An access key for another machine or program (shown once; only its hash is kept).
sushila keys list / sushila keys remove <name>Lists or revokes keys.
sushila logs [-f] [-n 40]The log of every action, from the web page, the commands and the queue (-f follows it).
sushila service install [--packs a,b] [--public] [--port N]Starts the server automatically (at boot or login).
sushila service removeStops starting it automatically.
While a server runs, install, remove, engine install, start and stop are sent to it and you see its progress: the server is the one place that changes anything, so the web page and the commands always agree.

Windows, macOS, Linux

The commands are identical. What differs is how you open a terminal, how you call the program, and a first-run security prompt.

Windows

Terminal: PowerShell, Command Prompt or Git Bash.
In the folder of the file: .\sushila.exe serve
Anywhere: put sushila.exe in a folder on your PATH, then sushila serve.
First run: SmartScreen may say "unknown publisher": More info → Run anyway.

macOS

Terminal: Terminal or iTerm.
chmod +x sushila once, then ./sushila serve
Anywhere: sudo mv sushila /usr/local/bin/, then sushila serve.
First run: if macOS blocks it, System Settings → Privacy & Security → Open Anyway (or xattr -d com.apple.quarantine sushila).

Linux

Terminal: any shell.
chmod +x sushila once, then ./sushila serve
Anywhere: sudo mv sushila /usr/local/bin/, then sushila serve.
NVIDIA: a recent driver is enough (the CUDA runtime comes with the engine).

Serving and the web page

sushila serve runs one web server on one port (default 8765). The page has two tabs:

  • Use: chat, code, images, music and video with the running models; a background queue for long jobs.
  • Admin (this computer only, with the admin password): Packs (install, start, stop, verify, remove), Engine, Queue, Logs, Settings.

Every page has the ☰ menu with Use, Admin and this documentation. Each running model's engine listens on an internal port (8766, 8767, …) on 127.0.0.1 only; the server forwards to it, so only the one port is ever exposed.

Accelerated or Standard: Accelerated uses Sushila's precomputed files for the model (faster); Standard is the plain model, as Ollama or stock llama.cpp would run it. Switch on the Use tab, or start with --standard.

Other machines and the internet

sushila serve --public --port 8844      # listens on all addresses
sushila keys add alice                  # prints a key once, e.g. sk-sushila-…
  • Browser: http://<server address>:8844/; the page asks for the key once and the browser remembers it.
  • From the internet: open the port in the firewall (and the router), then http://<public IP>:8844/.
  • Admin is never available from other machines, with or without a key.
  • --open: no key needed for chat and generation; anyone who can reach the port can use your GPU.
Plain http:// sends keys unencrypted. For use over the internet, put HTTPS in front: Cloudflare Tunnel, Caddy or nginx (any reverse proxy that forwards to the port works).

Admin password

  • First start: asked in the terminal (typed twice, not shown); without a terminal (double-click, service), the Admin tab asks for it the first time, and only on this computer.
  • Stored as a one-way hash (Argon2id) in the file adminpassword in the data folder; it cannot be read back.
  • Change it: Admin → Settings, or sushila password. Both ask for the current password first. Other browsers are logged out.
  • Lost it: on this computer, sushila password --reset sets a new one without the old one. Every old login ends.
  • The commands themselves never need the password: they run as you, on this computer.

API (OpenAI-compatible)

curl http://localhost:8765/v1/chat/completions \
  -H "Authorization: Bearer <key>" -H "content-type: application/json" \
  -d '{"model":"qwen3-4b-instruct-2507","messages":[{"role":"user","content":"Hello"}]}'
PathWhat
/v1/chat/completions, /v1/completionsText (streaming supported); "model" names a running pack.
/v1/modelsThe running models.
/v1/images/generationsImages.
/v1/video/…, /v1/music/…Video and music jobs (used by the page).
/api/stateInstalled packs, running models, actions in progress.
/api/queueThe background queue.

Any OpenAI client works: base URL http://<server>:<port>/v1 and the access key as the API key.

Files and folders

Created the first time; nothing is searched for, and no administrator rights are needed. The program itself can live anywhere.

SystemData folder
Windows%APPDATA%\ai.sushila.hoststation
macOS~/Library/Application Support/ai.sushila.hoststation
Linux~/.local/share/ai.sushila.hoststation

Another folder: --data-dir <folder> or the environment variable SUSHILA_HOME. Inside:

engine/<version>/Sushila.cpp (text, image/video and music engines)
packs/<pack>/Installed model packs
logs/sushila.logEvery action, with its source (page, cli, server)
logs/<pack>.logThe engine output of each model
outputs/, queue.jsonFinished queue jobs (images, songs, videos, texts) and the queue
state.jsonSettings, installed packs, what runs (written only by the server)
adminpassword, admin-cli.tokenThe admin password's hash; the commands' private token
downloads/Partial downloads (resumed automatically)

Troubleshooting

  • First step, always: sushila selftest, then sushila logs -n 60.
  • "port is busy": another server already runs (sushila status), or use --port.
  • A model does not start: its engine output is in logs/<pack>.log. If the GPU engine cannot load a model (e.g. an old driver), Sushila switches to the next engine (CUDA → Vulkan → CPU) by itself and says so in the log; sushila engine install tries the GPU again after a driver update.
  • Slow: sushila engine info shows whether the GPU is used; the model's log shows how many layers are on the GPU.
  • A download stopped: run the same command again; it resumes.
  • A pack seems damaged: sushila verify <pack>; reinstall it if a file is listed.
  • Lost the admin password: sushila password --reset on this computer.
